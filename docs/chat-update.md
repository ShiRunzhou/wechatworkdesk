# 固定工作聊天增量更新

双击项目根目录的 **更新工作聊天.cmd**。保持 WeFlow 打开、原账号和数据库连接可用。
范围固定为 `workdesk/chat_update.py` 的 11 个 external_id，不按显示名合并。
每次以点击执行的时刻为终点，往前 604800 秒（滚动七天），显示为北京时间。

首次配置：WeFlow 左下角账号菜单 → 设置 → API 服务 → Access Token「随机生成」，开启 HTTP API 服务；监听地址保持 `127.0.0.1`、端口 `5031`。
程序直接读取本机 WeFlow 配置，用 Authorization 请求头认证。不要把令牌发送到聊天或存入项目。
程序不会改动安装资源、发送微信消息、删除微信数据，也不调用大模型。

## 文件和结果

- 原有 `E:\wechatrecord\texts`、Markdown、附件均只读保留。
- 新增消息逐条保存于 `E:\wechatrecord\increments\<external_id>\<时间戳>-<标识哈希>.md`；图片在同会话 `media` 子目录。每条文档含会话 ID、消息标识、北京时间和来源。
- 索引、进程锁和每次报告位于 `D:\wechatworkdesk\data\chat-update`，不写入事项台数据库，不修改人工状态、反馈或事项编号。
- 各会话显示新增数、跳过数、语音转写缺口、附件缺口、错误。缺口以本次扫描范围内的消息为准；失败会话的零缺口不代表完整。
- 每次完成会话后生成独立的 `inventory-<编号>.json` 阅读索引：消息标识唯一，优先指向可匹配的旧 Markdown，列出已有附件；旧格式无法可靠比较时标记 `possible_old_format_overlap`。请以后续报告中的 inventory 为入口，不将所有历史增量文档简单拼接。
- 双击 **重试更新失败聊天.cmd** 只重试最近报告中失败的固定会话。直接重新运行完整更新也安全。
- 每次报告有独立文件名，保留历史；失败后已写入的消息保留，下次跳过并继续。进程崩溃后从已生成文档恢复索引。

## 去重和旧导出

优先使用会话 ID + serverId；无 serverId 时使用 localId、时间、sortSeq、类型的组合。
没有可靠标识则报告失败，不猜测同一条消息。已有 WeFlow Markdown 通过文件内会话 ID 关联，只有时间、发送人、内容都可靠匹配才跳过；媒体还可通过消息局部编号匹配。
旧语音文件名中的 serverId 可用于复用既有转写（音频即使已经删除也可读取文字）。程序也直接读取 WeFlow 本机 `Voices/transcripts.json`，按会话ID+消息时间+localId精确关联缓存。旧 Markdown 无稳定消息编号时，保守匹配不能保证每种特殊消息都跨格式去重；未能可靠匹配的首次增量可能重复呈现旧消息，后续运行按稳定标识去重。不会因为会话文件存在而跳过整场会话。

缺图补齐时另写 `-attachment.md` 补充文档，旧文档不改写。后续 Agent 应将同 external_id 的原导出和增量一起作为资料，沿用消息标识；程序没有自动创建分析轮次或发布事项。

## 当前接口限制

本安装版 `/api/v1/messages` 支持图片；媒体导出函数没有普通文件导出分支。因此新文件消息保留文本，并明确报告文件附件缺口；原来已经存在的文件附件保持原位。
WeFlow 自带本地 SenseVoiceSmall 转写功能。本机模型在 `C:\Users\shiru\Documents\WeFlow\models\sensevoice\model.int8.onnx`（239233841字节），配套 tokens.txt 已存在；WeFlow 内部通过 transcribeWavBuffer 调用模型。它的聊天/导出功能通过内部 IPC 调用 getVoiceTranscript；本安装版 HTTP 路由没有提供新语音转写调用。本程序不生成或下载任何音频，不使用临时音频。旧转写或本机缓存可匹配则复用，无法匹配的语音报告转写缺口，不能视为已完成转写。以后若有新语音缺口，可先在 WeFlow 中转写，再重跑；补充文字另写 `-transcript.md`，原增量文档不变。
WeFlow 内部图片解密结果存于其自身 api-media 缓存；本程序只复制到新增目录，不覆盖旧附件。
未包含视频、表情导出和模型分析。
