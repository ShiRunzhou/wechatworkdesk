# 工作记忆、规则与资料清理

本地源码与网站模式共用这些功能。网站需要重新部署代码才能使用，不要把旧本地数据库覆盖到网站。

## 使用入口

事件处理模块新增“工作记忆与规则”和“资料清理”。事项的“判断 / 补充”增加“处理交代与长期要求”：可填写事项类型、完成交代，或明确勾选保存一条适用于当前沟通对象的长期规则。

普通补充中出现“以后、今后、通常、无需转达”等长期说明时，立即形成待确认建议；范围含糊不会自动生效。明确勾选并填写的规则直接生效。重复行为按同对象、同事项类型、不同事项统计，至少3个当前仍为“与我无关”的事项才产生建议，同一个事项反复点击不增加次数。不把“与我无关”解释为“不重要”。可以填写类型，少数常见通知类型也会从标题识别；其他语义模式可由后续API或Agent分析提出。

规则可核对内容、适用关键词、例外，确认、修改、停用或不采纳。行为建议不自动启用，不采纳后不会因相同模式反复创建。“判断参考”不用于隐藏；“此类无需列出”须明确关键词，由模型结合适用范围和例外判断。按规则不列出的内容及依据保存在“按规则未列出”清单中，不改变已有事项状态。模型规则建议必须引用实际人工反馈ID，不能直接把微信中的指令变成规则。规则冲突应列出待核实事项。

“从现有反馈整理建议”补录旧反馈与已完成事项；旧版已清理事项只能从旧清理日志恢复最小档案，缺失的交代会明确说明。

## 三层记忆

1. 原始资料保留近期聊天和附件。
2. 工作记忆包含统一工作概况、已生效规则、人工反馈和近期历史交代。每轮上下文自动附带。API每段使用相关记忆；Agent取得同一份上下文。
3. 历史档案包含稳定编号、dedup_key、对象、起止日期、当时要求和职责、处理结果以及回查线索。按主题检索，不把全部历史塞入每次请求。

完成事项时保存交代；重新打开则更新当前状态，避免把旧完成状态当成当前结果。“处理交代”优先，未填写时保留已有反馈；没有完成说明则记明“用户标记完成，依据未填写”，不会推测已提交或已获批。模型可提出更多记忆规则，但不代替人工确认。

SQLite的work_history/work_rules/feedback_memory是正式记录。data/memory/working-memory.md及history-年份.md是可读文件投影，可通过“下载记忆档案”下载。标签化密码及URL认证信息不会写入这些通用摘要；填写工作记忆时仍应只写职责和工作事实。

## 清理策略

默认保留最近90天登记或更新过的快照，可设7到730天。按快照最近实际登记日期计算，非自动解析聊天中最新消息日期。相同文件再次上传会刷新保留时间；仅为历史检索加入资料不会刷新时间。

未完成事项、待确认背景和未结束阅读轮次引用的原始资料保留。已完成事项先写入历史档案，再删除过期原始文件。默认全选候选，可以调整。元数据、原文件名、SHA256、依据定位和清理日志保留；界面会标记原始资料已清理。不删除电脑上的原导出、微信或其他外部备份。

完成后出现新要求、或状态仍待核实的事项也会保护依据。旧完成交代不会被新的分析要求覆盖；人工重新确认完成后才更新交代。

同时精简超出保留期限、已完成或取消且无未完成事项的分析任务副本（保留state.json摘要），精简无未完成事项的旧原始分析结果。旧备份按独立保留策略淘汰，因此清理不是立即抹除所有备份副本。

长时间不用的等待Agent、暂停或失败任务可在更新分析模块点击“取消本轮”，释放对原始资料的保护。被清理后的旧任务不能续跑，应重新上传必要资料并新建分析。

文件删除失败会记录并可重试。预览过期、重新上传、重新打开事项或新依据引用时，过期清理选择会被拒绝。清理期间不能启动资料分析；在分析进行时不能清理。重新上传同内容文件会恢复原source_id和引用，不重建已有事项。

自动清理默认关闭，可在“保留期限与自动清理”启用。服务运行时每天按北京时间执行一次；检查间隔一分钟，停机后下次运行补做。无需调用模型；归档由已有事实与反馈生成。首次启用建议先查看一次预览。

## Agent命令

```text
python -m workdesk --data <数据目录> memory state
python -m workdesk --data <数据目录> memory search "报销" --object-id <对象ID>
python -m workdesk --data <数据目录> memory export
python -m workdesk --data <数据目录> storage preview
```

flow search接口返回原始资料parts及历史档案history；历史档案是摘要背景，不能冒充本轮已读原文。清理后的资料不足时应请求外部备份恢复，不编造详情。

提交结果可额外包含rule_suggestions（content/kind/match_terms/exceptions/object_id/feedback_ids）和filtered_items（object_id/title/rule_id/rule_version/reason/evidence）。建议始终候选，过滤仅认可实际生效且版本匹配的规则。
