# 设计与版本路线

## 目标

近期：可靠识别重要工作信息，整理可核查、可反馈、可交接的事项。

长期：基于阅读记录和人工反馈，逐步建立对用户工作场景、职责与关系的认识；经人工确认后可向 WeChatAgent 提供受控资料。深入阅读不等于模型一次读完全部历史，完整理解不能作为无条件保证。

## 两条使用路径

主要路径从阅读需求开始：需求 → WeFlow 导出 → Agent 登记资料并阅读 → 结果提交 → 工作台反馈 → 交接 → 回传。

已有事项的路径从工作台开始：查看需要关注 → 判断/补充 → 协助推进 → 更新状态。没有新导出时不需要重新分析。

Agent 是阅读操作者；项目是事实、资料与状态的长期保存位置。新 Agent 通过上下文接口继续工作，不依赖之前聊天记忆。项目不会自动创建 Codex 任务或向其他聊天发送交接包。

## 资料层、认知层、事项层

- 资料层：原始导出与附件快照、文件哈希、对象、声明时间覆盖、每轮实际阅读说明。文件名相同但内容改变视为新版本。
- 认知层：有依据的背景/职责建议，经用户确认后成为下一轮上下文。最新确认版本生效，历史版本可查看；未确认内容不得包装成事实。
- 事项层：标题、通知时间、原文期限、责任、行动、缺口、依据与稳定标识。每轮分析建议与人工状态分别保存。
- 反馈层：人工状态、纠正和完成回传；保持人工作用，不把“有交接包”当成“已完成”。

通知可能被修订、取消，可能重复或仅针对别人。第一版由 Agent 提出变化和疑问，用户判断；不自动取消或完成事项。

## 第一版 V1 · 已实现的底座

本地保存、Agent 命令行契约、逐文件阅读声明、事项列表、人工反馈、背景确认、历史结果与交接包。首批真实资料未导入，WeFlow 的具体 JSON/Markdown 结构、附件阅读覆盖和现实事项准确率尚待实测。

## 第二版 V2 · 使用反馈后推进

- 使用真实导出样本建立解析适配器，生成稳定消息定位，区分新增消息与重导出历史。
- 深度阅读分段与背景/项目时间线；大材料阅读进度、跨轮恢复与主动补缺口。
- 提供有证据的跨群重复/通知更正候选，由人工确认合并；避免错误影响已处理状态。
- 从反馈产生认知候选，支持冲突、有效期与依据；不自动把行为解释升级为事实。
- 根据验证选择 API、本地模型或主 Agent 的子任务分工。任何材料外发/模型调用须遵循用户授权。

## 第三版 V3 · 受控知识共享

- 导出人工确认、按账号/对象限定的稳定职责、关系和沟通资料，供 WeChatAgent 使用。
- 临时事项不作为全局画像，凭据不作为通用知识；先单向导出，再评估同步。
- 外部任务结构化回传、冲突与完成证据核对；不自行拓宽发送/执行权限。

以真实使用和验收推进版本，不能按天数自动升级。未来功能不得在界面或汇报中宣称已完成。
